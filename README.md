# Чеклист відкриття ресторану — Telegram-бот + Supabase + панель звітів

## Що всередині
| Файл | Що це |
|---|---|
| `supabase/migrations/` | Таблиці, захист доступу, сховище фото, 8 ресторанів і стартовий чек-лист (17 пунктів у кожному) |
| `supabase/functions/telegram-bot/index.ts` | Бот (Supabase Edge Function) — без окремого сервера |
| `.github/workflows/deploy.yml` | Автодеплой бази, бота й панелі |
| `reports/camera.html` | Камера всередині Telegram (Mini App) — фото без доступу до галереї |
| `reports/index.html` | Панель звітів: огляд, звіти з фото, проблеми, підтвердження персоналу, редагування чеклиста |

## Як це працює
1. Працівник пише боту `/start` → вводить імʼя → обирає свій ресторан.
2. Ти підтверджуєш його в панелі (вкладка «Співробітники») і за потреби додаєш інші ресторани — у працівника їх може бути кілька.
3. Працівник тисне **«▶️ Почати чеклист відкриття»**. Якщо ресторанів кілька — спершу обирає, який відкриває, далі йде по чек-листу саме цього ресторану.
4. На «Ні» або число поза нормою (напр. холодильник > 5 °C) бот просить коментар — це рахується як **проблема**.
5. Після завершення — короткий звіт у групу керівників (якщо задано `REPORT_CHAT_ID`).
6. Якщо перервався — повторне натискання продовжує з того ж місця. `/cancel` — скасувати.

**Окремий чек-лист на ресторан.** Вкладка «Чек-листи»: обери ресторан, додавай/редагуй/вимикай пункти. Кнопка «Копіювати» переносить пункти з іншого ресторану — зручно для старту.

**Вікно виконання.** Вкладка «Ресторани»: для кожного — «Починати з» і «Завершити до». Раніше початку бот не дасть стартувати; завершено після кінця — **запізнення**.

**Фото лише з камери.** На кроці з фото бот показує кнопку «📷 Зробити фото» — вона відкриває камеру всередині Telegram (`reports/camera.html`, Mini App). Галереї там немає; на знімок ставиться штамп часу. Фото, надіслані в чат звичайним способом, бот відхиляє. Сервер перевіряє підпис Telegram, тож надіслати фото від чужого імені чи до чужого чеклиста не можна.
При першому відкритті Telegram попросить дозвіл на камеру — його треба дати.

**Запізнення** = чеклист завершено пізніше `open_time` ресторану (за замовчуванням 10:00 — зміни в Supabase → Table Editor → `restaurants`).

## Деплой через GitHub (автоматично при кожному пуші в `main`)
Workflow `.github/workflows/deploy.yml` сам: застосовує міграції бази → оновлює секрети й код бота → ставить вебхук Telegram → публікує панель на GitHub Pages.

### Один раз налаштувати
1. **Telegram:** @BotFather → `/newbot` → токен.
2. **Supabase:** створи проєкт (запамʼятай пароль бази). Ref — частина адреси `https://<REF>.supabase.co`.
3. **GitHub → репозиторій → Settings → Secrets and variables → Actions:**

   | Тип | Назва | Звідки |
   |---|---|---|
   | Secret | `SUPABASE_ACCESS_TOKEN` | supabase.com → Account → Access Tokens |
   | Secret | `SUPABASE_DB_PASSWORD` | пароль бази з кроку 2 |
   | Secret | `SUPABASE_PROJECT_REF` | ref проєкту |
   | Secret | `TELEGRAM_BOT_TOKEN` | токен бота |
   | Secret | `TELEGRAM_WEBHOOK_SECRET` | будь-який довгий випадковий рядок (лише латиниця, цифри, `_`, `-`) |
   | Secret | `REPORT_CHAT_ID` | необовʼязково: id групи керівників |
   | Variable | `SUPABASE_ANON_KEY` | Supabase → Project Settings → API Keys → anon / publishable |

4. **Settings → Pages → Source: GitHub Actions.**
5. Запусти Actions → Deploy → Run workflow (або просто пушни в `main`).
6. **Доступ до панелі** (у Supabase):
   - Authentication → Users → Add user (email + пароль, Auto confirm);
   - SQL Editor: `insert into dashboard_admins (email) values ('твій@email');`
   - Authentication → Sign In / Providers → вимкни «Allow new users to sign up».

Панель буде за адресою `https://<github-user>.github.io/<repo>/`.

> GitHub Pages на безкоштовному тарифі працює лише з публічним репозиторієм. Секретів у коді немає (anon-ключ публічний за задумом, дані захищені правилами доступу), але якщо репозиторій має бути приватним — потрібен GitHub Pro/Team або хостинг панелі на Cloudflare Pages.

### REPORT_CHAT_ID
Додай бота в групу, напиши там повідомлення, тимчасово викличи `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`, потім `.../getUpdates` → візьми `chat.id` (від’ємне число). Після цього перезапусти workflow — він поверне вебхук.

### Зміни в базі
Нові зміни схеми — новим файлом у `supabase/migrations/` (наприклад `20261105120000_add_x.sql`). Старі міграції не редагувати.

## Налаштування чеклиста
Вкладка «Чеклист» у панелі: додати пункт, змінити текст/порядок, вимкнути. Пункт можна зробити спільним або лише для одного ресторану. Для числових пунктів задай мін/макс норму.

## Безпека
- Бот працює з ключем service_role всередині Supabase — він ніде не світиться.
- Панель бачить дані лише для email із `dashboard_admins`; фото приватні, відкриваються тимчасовими посиланнями на 1 год.
- Вебхук перевіряє секрет — чужі запити до функції відхиляються.
